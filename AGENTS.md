# Architecture rules
- The product is a native Android app (Capacitor); the Lovable web preview is dev-only. Why: user requirement, the APK is the deliverable.
- All data access goes through `Repo` (src/lib/db/repo.ts) over the `SqlDb` interface; every project-scoped method requires `projectId` and filters by it. Why: project isolation is a hard requirement and is unit-tested.
- Native storage = SQLCipher via @capacitor-community/sqlite; preview/tests = sql.js with the same SQL. Never use IndexedDB/localStorage as product storage.
- Preview sql.js mutations must persist synchronously before resolving; never debounce database writes. Why: a successful save must survive immediate reload and report storage failures instead of silently losing data; native SQLCipher remains unchanged.
- API keys are stored only as AES-GCM ciphertext; the AES key lives in Keystore-backed secure storage. Never log keys or include them in exports.
- `android/` is generated by `scripts/android-prepare.sh` (CI and local), not hand-edited; put native tweaks in that script. Why: reproducible builds.
- Provider calls run on-device from the WebView (user's own keys), no server functions.
- Azure OpenAI uses a distinct provider kind; derive its stored display name/model from deployment and normalize URLs in the shared adapter, selecting deployment in the body for /openai/v1 and in the route for legacy endpoints. Why: the same setup supports testing, saved retests and chats with both Azure API contracts.
- Provider diagnostics and real-response validation live in the shared on-device provider adapter; verification status uses a separate SQLite table, and restoring backups resets verification because credentials are excluded.
- Android self-tests use a shared sentinel recovery check to exercise password encryption, deletion and restoration through Repo; unit coverage validates the check without claiming native execution. Why: emulator reports must not mistake dump-only checks for recovery testing.
- Universal routing requires exact capability, executable adapter and declared limits; revalidate before secrets/jobs/network. Auto prefers verified Azure and open SearXNG; manual/favorite choices remain. Why: declarations must not cause incompatible calls.
- AssetStore uses per-file-DEK AES-GCM wrapped by versioned Keystore keys; public decryption authenticates the complete file before output and pins rereads by digest. Why: no provisional plaintext or cross-project leakage.
- Document extraction/export is lazy-loaded on-device; text tasks use exact chat routing. Why: offline-first reading without a server.
- Agents/workflows are project-scoped declarative records orchestrated through Repo, exact-capability routing, explicit tool permissions, call limits and per-step approval; ambiguous interruptions require confirmed retries. Why: model output must never grant permissions or duplicate billed actions silently.
- User JavaScript executes only in a separate worker using QuickJS WASM with no host objects/modules, bounded memory, stack, time and output; no eval in the application or native shell bridge. Why: generated code must not access storage, network or credentials.
- Remote SSH/SFTP use the generated MiaiRemote Android plugin with strict known_hosts checking and a native confirmation for each request; encrypted connection secrets are excluded from backups, and no local shell is exposed. Why: commands must never silently acquire device or server access.
- Workspace links and deliverables remain project-scoped through Repo; professional data statistics and cost scenarios run locally with deterministic formulas. Why: reusable professional tools must preserve project isolation and distinguish calculations from predictions.
- Native schedule triggers use inexact Android alarms containing opaque schedule IDs only and lead to user review; they never execute provider calls or grant permissions. Why: closed-process reminders must survive reboot without silently performing billed actions or exposing project data.
- Remote media jobs persist the provider task ID before polling; polling never resubmits generation, and output downloads omit credentials and reject redirects. Why: recovery must not duplicate billed tasks or leak user keys to asset hosts.
- GLB previews dynamically load Three.js after mount and block external GLB resources. Why: native/browser SSR safety and preventing untrusted model files from fetching external data.
- Chat attachments use AssetStore encrypted originals and Repo project-scoped message links; images use provider-native multimodal payloads only for models declaring vision. Why: chat files must survive reload without crossing projects or silently dropping images.
- Shared navigation uses a desktop sidebar and accessible mobile drawer with a full-height chat area; safe Markdown excludes raw HTML. Why: broad tools stay discoverable without shrinking conversations or executing model-generated markup.
- Audio edits use deterministic PCM/WAV processing; video export uses pinned Android Media3 with private transient cache cleared after completion/error and startup. Why: real local media engines must preserve encrypted originals and never expose a shell.
- Realtime voice is a separate on-device WebRTC session; user keys mint short-lived provider tokens, only authorized project context is sent, and no model tool execution is enabled. Why: bidirectional voice must not be conflated with dictation/TTS or bypass tool approvals.
- Debug APKs must use `signing/miai-debug.keystore`, never a regenerated key. Why: signature changes prevent data-preserving updates.
- Manual model/provider forms verify exact drafts before saving; draft credentials stay in memory. Why: supplementary setup must not bypass real-response verification.
- SearXNG uses an explicit HTTPS JSON instance, on-device form POST without keys/proxy; validate source URLs. Why: open search without mandatory app backend or unsafe links.
