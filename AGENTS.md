# Architecture rules
- Visual glass is defined centrally in src/styles.css with standard backdrop-filter only, static surfaces, no nested blur and opaque fallbacks. Why: consistent rendering and bounded compositing on Android.
- The product is a native Android app (Capacitor); the Lovable web preview is dev-only. Why: user requirement, the APK is the deliverable.
- All data access goes through `Repo` (src/lib/db/repo.ts) over the `SqlDb` interface; every project-scoped method requires `projectId` and filters by it. Why: project isolation is a hard requirement and is unit-tested.
- Native storage = SQLCipher via @capacitor-community/sqlite; preview/tests = sql.js with the same SQL. Never use IndexedDB/localStorage as product storage.
- Preview sql.js mutations must persist synchronously before resolving; never debounce database writes. Why: a successful save must survive immediate reload and report storage failures instead of silently losing data; native SQLCipher remains unchanged.
- API keys are stored only as AES-GCM ciphertext; the AES key lives in Keystore-backed secure storage. Never log keys or include them in exports.
- `android/` is generated by `scripts/android-prepare.sh` (CI and local), not hand-edited; put native tweaks in that script. Why: reproducibility.
- Provider calls run on-device from the WebView (user's own keys), no server functions.
- Azure OpenAI: `src/lib/azure-url.ts` normalizes any portal URL to resource or /openai/v1; each deployment's type is `miai_kind` in extra_params (inferred, overridable), tested by a real request of that type; non-chat types stay out of text chat. Why: one form must verify and route every deployment type.
- Provider diagnostics and real-response validation live in the shared on-device provider adapter; verification status uses a separate SQLite table, and restoring backups resets verification because credentials are excluded.
- Android self-tests use a shared sentinel recovery check to exercise password encryption, deletion and restoration through Repo; unit coverage validates the check without claiming native execution. Why: dump-only checks are not recovery tests.
- Universal routing requires exact capability, executable adapter and declared limits; revalidate before secrets/jobs/network. Auto prefers verified Azure and open SearXNG; manual/favorite choices remain. Why: declarations must not cause incompatible calls.
- AssetStore uses per-file-DEK AES-GCM wrapped by versioned Keystore keys; public decryption authenticates the complete file before output and pins rereads by digest. Why: no provisional plaintext or cross-project leakage.
- Document extraction/export is lazy-loaded; OCR worker, WASM and languages ship locally. Why: first-use offline reading.
- src/lib/automation, src/lib/nodes, src/lib/code, src/lib/media and pc-node have their own AGENTS.md; read them before changing those directories. Every agent tool call goes through invokeTool(). Why: one gate for permissions, budget, approvals and recovery.
- User code (JS/TS/Python) runs only in isolated, bounded workers; see src/lib/code/AGENTS.md. Why: generated code must not access storage, network or credentials.
- Autonomous runs never require a PC: the phone workspace is the default environment; a PC Node folder (on a PC or a VM) or saved SSH servers (native confirmation per command) are optional extensions. Why: agents must work independently of any paired machine.
- Remote SSH/SFTP use the generated MiaiRemote Android plugin with strict known_hosts checking and a native confirmation for each request; encrypted connection secrets are excluded from backups, and no local shell is exposed. Why: commands must never silently acquire device or server access.
- Workspace links and deliverables remain project-scoped through Repo; professional data statistics and cost scenarios run locally with deterministic formulas. Why: reusable professional tools must preserve project isolation and distinguish calculations from predictions.
- Native schedule triggers use inexact Android alarms containing opaque schedule IDs only and lead to user review; they never execute provider calls or grant permissions. Why: reminders survive reboot without billed actions or data exposure.
- Remote jobs persist task IDs before polling; never resubmit on recovery. Azure Sora v1 uses fixed same-origin content paths; arbitrary output URLs get no keys and reject redirects. Draft video tests are durable jobs. Why: prevent duplicate billing/key leaks.
- Chat attachments use AssetStore encrypted originals and Repo project-scoped message links; images use provider-native multimodal payloads only for models declaring vision. Why: chat files must survive reload without crossing projects or silently dropping images.
- Chat answers are saved while streaming (`src/lib/chat-draft.ts`, `message_status` streaming/interrupted) under the shared foreground notice; interrupted answers offer "Continuar" appended to the same message. Why: closing the app or locking the screen must never lose generated text.
- Shared navigation uses a desktop sidebar and accessible mobile drawer with a full-height chat area; safe Markdown excludes raw HTML. Why: broad tools stay discoverable without shrinking conversations or executing model-generated markup.
- Media uses local Web Audio/PCM masters, JSCAD solids and Android Media3; advanced FFmpeg/Demucs run only on an approved paired PC, with chunked encrypted RPC, durable sessions and cleanup after encrypted import. Why: real engines without a phone shell or mandatory backend.
- Realtime voice is a separate on-device WebRTC session (OpenAI or Azure OpenAI GA /openai/v1); user keys mint short-lived tokens, only authorized project context is sent, and optional voice tools are a fixed allowlist executed only through invokeTool() inside a `voice` run, holding the tool result until any required approval. Why: bidirectional voice must not bypass tool permissions, budgets or approvals.
- Debug APKs must use `signing/miai-debug.keystore`, never a regenerated key. Why: signature changes prevent data-preserving updates.
- Manual model/provider forms verify exact drafts before saving; draft credentials stay in memory. Why: supplementary setup must not bypass real-response verification.
- SearXNG uses an explicit HTTPS JSON instance, on-device form POST without keys/proxy; validate source URLs. Why: open search without mandatory app backend or unsafe links.
- Project import creates a new project; backups v3 are per-record AES-GCM, verified fully before a journaled restore; budgetGate runs before credentials. Why: no merges, partial restores or unconfirmed overspend.
- Chat tools are a fixed allowlist in src/lib/chat-tools.ts offered only when runnable, via OpenAI-style native tool calls (OpenAI/Azure fall back to /responses if chat/completions rejects tools; reasoning_content is stored per message and resent, never shown/exported; the prompt lists tools only when sent); each call runs through invokeTool() inside a `chat` run and created files attach to the assistant message. Phone-capable tools live in src/lib/automation/phone-tools.ts as ordinary ToolDefs (HTTP is public-https-only, archives use local 7-Zip WASM in public/7z, local SQLite databases are encrypted assets with a new version per write); PC/VM work from chat goes only through approval-gated pc.exec/ssh.exec. Why: the chat reaches app capabilities without bypassing permissions, budgets or approvals.
- Device integration (Guardar como, Compartir en…, received shares, agents' foreground notice) goes through the MiaiDevice plugin and `src/lib/device.ts`; only app-cache files are saved/shared and the inbox accepts only content:// from other apps. The app is edge-to-edge: MainActivity reports system-bar/cutout/keyboard insets as CSS vars (--sat/--sab/--kb) used by the shell; Bluetooth transfers are password-sealed files inside a ZIP, never with API keys. Why: no confused-deputy access.
- Large files move in 1 MB pieces (`blobChunks`, `AssetStore.stream`) and native media exchanges cache file paths, never whole-file base64. Why: WebView memory.
- Office editing (`docs/ooxml-edit.ts`) rewrites only touched XML parts; voice cloning requires a single-use on-device verification enforced in the executor. Why: keep design; no foreign voices.
- Azure auto-setup (`azure-autosetup.ts`) detects/types deployments and saves only really-tested ones. Why: easy setup, verified.
